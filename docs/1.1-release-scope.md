# Orbit 1.1 — release scope and acceptance gates

Orbit is a persistent workspace for agent and plain-terminal sessions, not a general-purpose IDE. This release follows the consolidated local-usage, telemetry, and implementation reviews.

## User-facing scope

- Cross-project activity/attention view, direct session navigation, unread results, and recent activity.
- Persist the last session per project; restore legacy data without losing sessions.
- Reversible session archiving, separate from deletion; do not silently interrupt working sessions.
- Plain terminals remain first-class; Cmd/Ctrl+T must not send a control character to the current PTY.
- Immediate, bounded, local session titles without a second Claude process or network request.
- Explicit failure/restart paths rather than pretending a spawned CLI proves a resumed conversation succeeded.

## Measurement and privacy

- No prompt, transcript, project name/path, secret, or raw exception message in remote telemetry.
- Telemetry disabled until settings initialize, consent respected immediately, development excluded.
- Stable analytic session semantics, idle expiry, meaningful durations and idempotent initialization.
- Distinguish terminal submissions from agent lifecycle signals. A working-to-idle transition means an agent turn stopped, not that a business objective succeeded.
- Treat historical dashboard figures as observations, not validated adoption/retention statistics.

## Release gates

1. Reproducible `npm ci`, TypeScript/build, complete frontend tests.
2. Rust formatting, tests, Clippy with warnings denied.
3. Independent code/security review with no unresolved release-blocking finding.
4. Isolated browser smoke with synthetic fixtures; no production data or paid agent calls.
5. Native macOS build/start smoke where supported; cross-platform CI builds/tests.
6. Audit production dependencies; disclose remaining development-only risk.
7. Version consistency, checksums, required installers and updater signatures verified.
8. Draft release first; publish only after artifact validation. Preserve the updater signing identity.
9. Disclose OS code-signing/notarization limitations; updater signatures are not OS trust certificates.

## Not in scope

Integrated code editor, marketplace, generic workflow engine, new agent providers, recording professional prompts, or a large customizable dashboard.
